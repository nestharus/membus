## 3. Wire and Python client

**F-E6-11 amendment:** [KV1.md](KV1.md) is the exact implemented slice-1 contract and supersedes this section's preliminary wire fields. Its sections 1/8 replace section 13.5's seq90 outage path/workload estimates; section 9 replaces fixed flush spacing with an initial configurable value and located F-LP-33 comparison. Slice 1 implements mutations/replay/health; the scan/cache/lifecycle/service requirements below remain later slices. This plan retains their design, not implementation claims.

Protocol **membus.kv/1**: persistent length-prefixed binary frames, LE u32 body length, u16 major, u16 minor, u8 opcode, u64 request ID, fixed fields then length-prefixed byte strings. Max frame negotiated; identifiers are UTF-8, values opaque bytes. hello carries offered major/minors, requested features, max frame and client identity; hello_ok returns chosen version, feature bits, instance epoch, server limits and current acknowledgement modes. No common major produces incompatible_version and close. Unknown optional features are reported absent; unknown opcodes return unsupported. Reject lengths/UTF-8 before allocations. Transport uses same encoder and dispatcher; no per-call subprocess. Batch may contain same namespace operations but is not an atomic multi-key transaction.

Pure Python uses struct, socket (TCP) or unbuffered binary pipe file, with read_exact/write_all loops and a bounded connection pool. A client thread owns a connection; request IDs multiplex only if the negotiated feature permits it. Pipeline/batch avoids one syscall roundtrip/row. Commands are a Rust CLI for people; the runtime holds the client object in-process. Explicit deadlines, reconnect backoff and retry with stable operation ID. Failed conditional operations are not blindly retried as fresh writes.

| Operation | Fields and reply |
|---|---|
| get / get_many | namespace + key(s), consistency committed(default) or speculative(opt-in). value, version, achieved_ack; hot/cache_miss/warm/cold-warming/expired/gone/missing/error distinguish. Committed reads never return queued mem-only versions. |
| put / conditional_put | key, bytes, op_id, expected_version or absent, ack=mem/os/flush, optional signal. Reply accepted version + achieved_ack, or conflict/current version; versions are opaque revision tokens. |
| remove | key, expected_version, op_id, ack. Tombstone persists; caller tool decides when data should be deleted. |
| scan_prefix / scan_range | namespace, byte lexical bounds, page count/bytes and stable snapshot cursor. Return keys+versions and optionally hot values; cold values return locations/token, not synchronous I/O. Numeric ordering is client's big-endian fixed-width key encoding. |
| fetch_hot / fetch_warm / warm_chunk | key+version/deadline: hot misses may cache after separate-pool I/O; warm data never caches; cold returns warming+request_id, warms into a shadow table, signals completion, then serves via the I/O pool. Does not share hot read executors. |
| subscribe / unsubscribe | namespace/key filter, subscriber id, pipe endpoint, protocol id/version and frame max. Reply installed or failed. |
| signal / timer_put / timer_remove | signal bytes and endpoint subscriptions; timers have id, due time/period, op_id, acknowledgement. timer changes persist as records. |
| namespace_policy / health | retention and rotation limits; epoch, capacities, queue lag, actual hot/cold status. Admin configuration only, no document schema parsing. |

No counter op in v1. A client counter is get plus conditional_put of a document, and the client chooses holes/order; opaque per-key revision tokens are internal conflict controls, not ordered streams. Graph edges use client keys link/<row>/<type>/<target>; graph traversal and snapshot reconciliation live in lane83. A scan guarantees its retained index snapshot, not a global transaction across writes. Limit cursor lifetime and bytes; stale_cursor is explicit. Initial key index admission cap 256 MiB; existing keys remain gettable, new keys fail capacity until index tiering is commissioned. This is a bounded first-client milestone, not an unbounded server claim.

## 4. Write, persistence and restart

**F-E6-20 realization amendment:** KV1's "implemented grouped write policy" and GROUPED-FLUSH.md define the current implementation. The proposed64row/144192byte limit below is now a selection budget; sync covers all earlier appended records, bounded by stripe admission1024items and queue_bytes/4chargedbytes. Gathering begins at the first idle waiter rather than merely waiting for a pre-existing ticket. The proposed1MiB os append cap is not implemented: existing kv/1 supports4MiBvalues with full-frame and queue bounds. Device spacing uses monotonic Instant. These explicit departures retain the original plan below as design evidence.

Four key-hash stripes, one append owner each. Validate/admit with a bounded per-stripe queue (16 MiB proposed, max 64 MiB across stripes). Reserve total memory before accepting. A per-key sequencer owns conflict checking and publication so two conditional writes cannot both accept the same revision. A mutation never waits holding a lock used by hot reads; values are immutable Arc snapshots. Publishing swaps a short shard pointer. Read-side snapshots can retain old bytes, so outstanding reader memory is charged and stalled readers have deadlines/admission quotas. This is the design; independent tests must establish actual lock reach and p99 effect.

Frame includes magic/version, length, namespace/key, immutable mutation ID/revision, ack class, value/tombstone, optional signal/timer and CRC. Append write_all handles partial writes. The code checks full frame before publication; default os publishes after append, flush publishes after covering flush. mem publishes to a speculative overlay and returns achieved_ack=mem; committed readers never observe it. Promotion/rollback generates explicit status; only a previously append-complete version may be evicted from the committed cache. Enqueue is not described as crash durability.

Drain os appends immediately, with admission/append cap1MiB. Flush waiters gather until the next device-wide50ms ticket; ordinary ledger tickets cover at most64rows/144,192bytes on one handle. A waiter completes only when that handle flush covers its offset. This replaces the earlier<=1ms gather proposal. No global fsync for unrelated keys. Queue overflow returns busy before acceptance or waits within client deadline. Read connections stay live while write queues fill. If disk fails, stop durable admissions, retain last committed snapshots and expose health=read_only; no silent downgrade to mem.

One source of truth: stripes containing namespace-separated segment chunks. Rotate on size (initial 8 MiB) or age (initial 60 s), not preallocate 256 MiB files on a shared drive without measurement. Persist the closed-chunk catalogue/marker with the same acknowledgement contract. On restart, exclusively own the data directory; enumerate catalogued chunks plus any files from interrupted catalogue updates, check headers and CRC, replay complete valid frames, retain interior-corrupt chunks for diagnosis, discard only verified torn final frames. Rebuild version/offset index. Do not let readers see a half-replayed index: handshake reports warming, then ready. idempotency IDs retained with their outcomes over a documented retry window (initial 24 h or namespace retention, whichever shorter); duplicate IDs beyond that return retry_window_expired where known, so clients must not assume permanent exactly once. Conditional current version remains an additional guard.

Read replay order within each stripe resolves one key; independent keys have no global order. A namespace's client event time is ordinary data. Index metadata always remembers retained key offsets, even when value cache evicts. Hot get neither opens a segment nor waits on write completion. A hot-tier cache miss returns cache_miss with a fetch token (fetch_hot may populate the bounded cache); a warm-tier read performs separate-pool I/O and never caches; a cold-tier read returns warming+request_id before the shadow exists. Thus the survey's “cold data reloaded” is retained on a separate path, adapted to the founder's newer tier words; a promise that arbitrary nonresident reads cost no drive I/O is left out as impossible for a bounded memory store.

## 5. Cache bounds and expiring chunks

Initial proposed process budget 512 MiB, configurable after actual size/rate answers: 128 MiB values, 256 MiB index, 64 MiB pending queues, 32 MiB protocol buffers and 32 MiB snapshots/timers/subscriptions; allocator/thread overhead measured and included in admission margin. Separate caps are upper allocations, not an RSS guarantee; reject new work before exceeding a calibrated whole-process budget. Long-lived pins cannot grow without limit. Byte-weighted approximate sharded LRU and time-to-idle drop cache bytes only. Cache TTL never changes data expiry, writes a file, or removes an offset.

**Late seq88, E-e17ce673d4034d699b9f82bda5e8e799 reopens cleanup scope.** Founder now gives membus rotation and expiring records: retire an entire chunk only after its newest record expires; base expiry on close/rotation time. Earlier cache-only eviction still holds. Segregate retention classes/namespaces into separate chunks within each stripe. Policy changes apply only to new chunks unless an explicit migration is commissioned; a closed chunk stores its immutable retention policy and UTC close time. retention=forever for authoritative ledgers/artifacts; leases diagnostic retention24h as section12; proposed 7 days for disposable router/codec logs, not a founder-chosen value.

No retention deletion on an open chunk. When close_time+retention has elapsed and no reader owns a chunk, mark its key references expired, durably publish retirement metadata, then delete that exact whole file. No rewriting or compaction of retained records. A repeated key may have later live versions; retire only references to this chunk, never later versions. Keep bounded per-chunk expiry summary and update index; get returns expired while the summary remains. Summary retention (proposed 30 days) bounds metadata; after that, missing is explicit and the client cannot infer never existed. A crash between mark/delete is retried idempotently; a file missing before mark is storage error, not clean expiry. Clock jumps: never retire earlier than a monotonic elapsed-time cross-check during a run; after restart, if wall clock validity is uncertain, pause expiry and report degraded until a stable basis is restored. These are implementation proposals, to be tested.

This **does** depart from the earlier “all deletion is another tool” reading for retention-enabled chunks, justified by the founder's newer located words. Explicit logical deletes for session/documents remain another tool's decisions through remove. Retention is record storage lifetime, not ordered streams.

**Late seq100, E-baa41591250c48dea3fc9242f125d72e extends section5 to optional per-table tiers.** Namespace policy describes chosen hot, warm, cold and gone stages with close-time ages; omitting a stage is valid. Hot retains an immediately readable bounded cache; warm serves drive bytes and never retains value bytes in memory; cold archives a compressed whole chunk on local drive or optionally cloud; gone is whole-chunk erasure. Transient decode/read buffers are charged to the I/O pool, not warm cache. Tier events rotated/warmed/cooled/erased carry namespace, chunk id, previous/new tier and operation id through section6 signals. Moving to warm drops affected hot cache entries without new payload writes. Moving to cold streams compressed archive to a temporary file, validates decoded bytes/checksum, flushes archive/catalogue, atomically switches metadata, then deletes the original only when readers release it. A kill at each step must retain a readable original or validated archive. Moves never rewrite records inside retained chunks; compression is a whole-chunk storage transition, explicitly added by newer words.

On a cold request, coalesce simultaneous requests for the same chunk, return warming+request_id immediately, unpack on the bounded I/O pool into D:/projects/membus/state/shadows/<namespace>/<chunk-id>, build a shadow index, then atomically publish it and emit warm. Shadow values follow warm policy and never populate hot cache. The shadow's configured warm lifetime applies independently of the archived canonical chunk; at expiry drop the shadow and return to cold, or to gone only when canonical retention permits. A shadow never resets a chunk's original close-time expiry. If archive is corrupt/unavailable, signal failed and leave cold status, not missing. A lost warm signal is recovered by retry/status(request_id); no polling transcript.

All stages are designed and optional; first build milestones deliver hot/warm/gone first and a local compressed cold slice next. The std-only cold slice specifies a bounded block RLE/literal archive (codec membus.chunk-rle/1), with decoded length, maximum block expansion, CRC, immutable original chunk digest and literal blocks for incompressible input. It is not a ZIP compatibility promise or a space saving claim; golden/fuzz/roundtrip and corruption tests are required. We prefer this narrow first codec over running uncleared compression crates. A replacement codec must have a new id and depguard-cleared pinned dependency and sandbox tests. Cloud is a designed optional backend with put/get/head/delete by immutable digest, retry and credential-reference supplied by its caller; **not selected for the first build**, because no cloud destination/credential holder is located and no secrets tool is commissioned. Local archival needs neither. Compression reads and writes at most one 8 MiB chunk at a time through an explicit maintenance command reserved in lineup disk:d; in-server work uses the bounded I/O pool in section13. The original+archive+shadow transient footprint is reported.

### Tiering alternatives and first slice

The founder makes hot/warm/cold/gone available and says not all tiers have to be used (design SHA074d2226, founder tier passage); age-based stages are claude2's interpretation. Compare: (A) fixed per-namespace close-age transitions as above, small deterministic policy but may send repeatedly read data to uncached warm storage; (B) explicit owner-triggered whole-chunk transitions, no read-frequency tracking, more caller policy but preserves a reused chunk as hot until the caller moves it; (C) automatic measured-reuse transitions, better working-set adaptation but metadata and timer overhead and a recurrence threshold still unmeasured. First hot/warm/gone slice supports A and B as policy choices; defaults are explicit namespace configuration, not a claim that age alone is optimal. Automatic C remains open until read-reuse/maintenance data can weigh it. Local cold is a later slice; compare whole-chunk literal archival with RLE compression and retain literal when savings <10%, as section13 requires. Cloud needs its owner/destination. Each form retains whole-file retirement and memory-only eviction.

## 6. Signals and timers

Delivery target is a named pipe independent of TCP/pipe client choice. membus stores generic endpoint and opaque protocol bytes; it contains no ccmsg wire adapter, session-file reader or ACP adapter. A subscriber specifies a writable pipe compatible with the payload; the request tool/Claude capability library formats Claude's inbox envelope. “Sent” means full payload written into the pipe; not that a recipient read it, a hook ran, or an agent is alive. Signal status distinguishes queued, written, deadline/pipe failure and cancelled. Dead pipes do not trigger process resurrection.

One bounded delivery queue and timer wheel per service, no per-agent polling process. Coalescing occurs only for explicitly marked coalescible wakeups, never requests with identities. Failed delivery stores failure status; persistent subscribers can retry within a bounded policy. Delivery may repeat across a crash after write and before status checkpoint; receivers use request IDs/acks if they need deduplication. Request tool alone defines receipt as receiver running ack(id), so no grep of transcripts.

Timed schedule records persisted; period 60 s is one allowed case. Restart fires at most one catch-up wakeup per timer by default, with missed count, not every missed interval; schema documents this. Scheduler's lease+due-id governs actual payload firing, so duplicate wakeups cannot authorize two jobs. Signal buffers and timers count within budget. Rates remain unlocated and configurable limits are stated in hello.

## 7. Leases interface and registry records for the router

Separate private nestharus/membus-leases is planned, not built. Proposed protocol **membus.lease/1** over conditional KV operations. Canonical resource spelling is `session:<stable-session-id>`; prior `session/<id>` examples are superseded. Parameters: Resource/Owner/RequestId are UTF-8 opaque ids; ProcessIdentity is `{pid:u32, creation_filetime:u64}` from kernel creation time, not a wall-clock guess; TTL is bounded 1–300,000 ms. LeaseToken is `{epoch:u64, claim_id:u64}`; Fence is the same monotonically allocated identity. Replies include remaining_ms, observed server UTC for diagnostics, current holder, request id and achieved ack. Owner identity can encompass many sessions on one process. All calls are proposed interfaces, not implemented availability.

| Exact call | Result and rule |
|---|---|
| acquire(resource:Resource, owner:Owner, process:ProcessIdentity, request_id:RequestId, ttl_ms:u32=120000) | LeaseGranted{token,fence,holder,process,remaining_ms,epoch,achieved_ack=flush} or Busy{holder,process,remaining_ms} or Refused{reason}. Atomic absent/expired acquisition; request_id deduplicates. `claim` is the old design name, not a second operation. Expiry alone cannot authorize a new host while the old one can still act. |
| renew(token:LeaseToken, request_id:RequestId, ttl_ms:u32=120000) | Renewed{token,fence,remaining_ms,epoch,achieved_ack=flush} or Stale/Expired/Refused. Token identifies resource and owner server-side; same unexpired token only, no resurrection. |
| transfer(token:LeaseToken, new_owner:Owner, new_process:ProcessIdentity, request_id:RequestId) | **Unsupported in v1**. A session move ends/quiesces the old host, verifies the PID+creation and supervised tree stopped, releases and reacquires a new fenced token; there can be a vacancy and acquire can lose the race. Atomic record transfer would not stop old native input or prove data-copy completion. A later transfer capability requires enforceable fence checks at both host effects and a quiescence/acceptance protocol. |
| release(token:LeaseToken, request_id:RequestId) | Released{epoch,achieved_ack=flush} or Stale/Refused; conditional same token, persisted release. Caller ends protected work before releasing. |
| inspect(resource:Resource) | Vacant or Holder{owner,process,token,fence,remaining_ms,epoch,authority_state}; diagnostic read, no authority to act. Supersedes `current`. |
| validate(resource:Resource, token:LeaseToken, fence:Fence) | Valid{remaining_ms,epoch} or Stale/Expired/Unavailable; synchronous check at a cooperating protected effect boundary, and host refuses mismatched fence. Unreachable is not valid. |

Forever control storage holds flushed service epoch plus claim-allocation high-water (section13.6); finite24h diagnostic chunks do not reset tokens. New epoch is persisted before ready; all old tokens lose authority across restart. Client computes its safe expiry from pre-send monotonic time + remaining_ms - safety margin100ms; reply later than that is unusable. ## 12. Review clarifications and bounded operating policy

These clauses qualify earlier provisional details wherever more specific. They are design commitments for the next build, not measured guarantees.

- **Immediate visibility and pending writes (O1/O2).** Admission copies a write into an immediately readable speculative overlay; a client can explicitly get(speculative). Default committed get waits for neither pending writes nor flushes and returns the last committed snapshot, so it may lag the overlay. os append does not wait for a flush gather window: drain append as work arrives, while flush waiters gather separately. Publication of an os/flush write is later than arrival in memory, a deliberate departure in default read semantics to preserve recoverable acceptance. Founder words do not specify who writes striped files: server-owned stripes match the remembered stripe/file bus but depart from lane83's per-writer-shard candidate. Both are named in section2; client spool would preserve writes before server admission at the cost of a file path per call. Here **pending in a killed-server claim means acknowledged os/flush**, not unacknowledged in-memory queue contents. Unacknowledged writes can disappear and clients retry stable op_id; no hidden survival claim.
- **Disk growth and replay (O3/O4/O7).** Authoritative historical rows require permanent retention until their owner changes policy; this imposes unavoidable growing disk usage. Initial total accepted log quota 8 GiB and high-water 6 GiB, configurable per device; at high water report capacity pressure, at quota refuse new writes before acceptance while reads continue. Existing files are never silently pruned. Rotation by age applies only to finite-retention namespaces, never empty chunks; forever namespaces rotate by size only. Leases use a dedicated **finite 24-hour diagnostic** namespace, max TTL 5 minutes; after restart epoch invalidation makes old records nonauthoritative. Every current lease lives in a newer unexpired chunk. They are not forever as the initial section7 proposed. Timer/config/counter current state namespaces remain forever with quota; new build must report footprint before acceptance. A generic conditional key counter inherits conflict and write costs, not magic lock-free sequencing.
- **Index checkpoint (O4).** To bound startup within quota, write a metadata-only index snapshot (key latest offset/revision, tombstone/expiry horizon, mutation outcomes, policy/chunk catalogue) after at most 16 MiB appended or 60 s of active writing. Flush referenced os records and snapshot metadata before atomically publishing snapshot pointer; replay only later complete frames. A snapshot accelerates lookup, never deletes or rewrites canonical retained chunk records. Broken snapshot falls back to full replay, up to the configured 8 GiB quota; bounded bytes are known, recovery seconds remain to measure. Snapshot bytes and cadence add D: traffic and must appear in load measurement; snapshot file generations bounded to two after valid publication. Separate admin tool may request a namespace-wide retention change/gone transition once the owner authorises it; a tombstone alone never promises physical reclamation in forever history.
- **Flush budget (O5/O6).** Per namespace separation creates several handles, so group commit means **one flush per touched handle**, not one per stripe globally. Cap active namespace/retention classes at 64 initially; refuse excess before file creation. Device-wide flush scheduler starts with a configurable cap **20 calls/s across all handles**; combine waiters on one handle, service fairly, never downgrade requested flush. Exceeding budget creates write-only backpressure/deadline failure before acceptance, not reader waits. The e2 final-build repeat replaces the earlier p99-derived lower-cap heuristic with fixed50ms spacing and measured completion tails separately (section13.4). Twenty calls/s is an initial scheduling target, not a measured<=10%device utilization guarantee. Runtime's located bursts may wait for batching; client deadline must include it. First production trial reports queueing and device co-tenant effects. Lease renewal defaults 30 s/TTL120 s reduce forced flush demand; chosen stronger flush leases require router owner review versus client's os request.
- **No old-value resurrection (O8).** Persist each key's latest revision/tombstone/expired horizon in the metadata snapshot before retiring any chunk, even if a newer chunk expires earlier after a policy change. Replay ignores any older revision behind that horizon, including old bytes still in a retained chunk. Expiry summary retention affects the displayed expired/missing distinction only, never erases the anti-resurrection horizon while older chunks exist. Charge this metadata to the index quota; inability to persist/update it postpones deletion. Add shortening-policy and tombstone regression tests.
- **Stripe count (O9).** Hash seed/algorithm and count are immutable in a data directory's header. A changed setting refuses startup; migration is a separately commissioned offline rewrite/import into a new directory with owner-visible cost, never an unnoticed remap.
- **Lease time/availability (O10/O11).** claim/renew replies carry **remaining_ms**, observed server UTC for diagnostics and epoch; no cross-process monotonic instant is sent as a deadline. Client starts its safety deadline from its own monotonic time captured **before** sending the request, adds remaining_ms and subtracts a negotiated safety margin (initial100 ms); slow reply past that deadline is unusable. validate is a synchronous control call, cost unmeasured; failure/unreachable refuses protected effect. During outage holders stop by local safe expiry, and loss of epoch stops authority earlier on reconnect. Restart invalidates all leases and can force fleet handover; no previous-owner priority is granted. Router may reclaim its own resource once it establishes/fences the old host, and must return blocked if that cannot be shown. This stronger availability tradeoff is explicitly proposed, with supervision owned by fleet manager, not claimed agreed behaviour.
- **Python reads (O13).** High-level Python get(value=True, deadline) resolves cache_miss, warm or warming through the appropriate separate path, including status retry if a signal was lost; low-level get_status exposes the original state. The client documents extra roundtrips and cold I/O. Only low-level hot get is certified free of disk reads. No working-set hit rate is claimed for the initial128 MiB value budget.

A proposed conservative index estimate256 B/key suggests ~917,504 ordinary keys at the224MiB admission ceiling (plus32MiB reserved control metadata), but actual overhead is measured before rollout.
